# libcamera Unicam Frame Synchronization

## Goal

Replace Picamera2 in the robot runtime with the direct Python `libcamera`
API. Every image passed to vision must carry the corresponding sensor frame
number for synchronisation with the STM32 IMU history.

The STM32 counts sensor STROBE pulses. The required number is therefore the
frame sequence produced by the Raspberry Pi Unicam CSI receiver, starting
from zero whenever the camera pipeline starts.

## Required Stream Setup

Configure two streams in every camera request:

- an ISP output stream (`main`) for the image consumed by vision;
- a RAW stream connected to Unicam, used only to obtain the sensor sequence.

Both buffers belong to the same completed `Request`. Do not request RAW in a
separate capture operation and do not pair frames by timestamp alone.

## Correct Sequence Source

Use the metadata of the RAW/Unicam frame buffer:

```python
sensor_sequence = request.buffers[raw_stream].metadata.sequence
image_buffer = request.buffers[main_stream]
```

`FrameMetadata.sequence` is exported by the libcamera Python bindings. It is
copied from the V4L2 buffer sequence. The BCM2835 Unicam driver resets it when
streaming begins and increments it for frames generated by the sensor, not for
buffers dequeued by userspace. Gaps identify frames dropped by the capture
pipeline.

The ISP output node has its own output-buffer sequence. It often happens to
match the Unicam sequence, but it is not the authoritative sensor number and
must not be used for IMU synchronisation.

Also do not use `Request.sequence`: it is libcamera's request sequence, not
the CSI receiver sequence.

## Temporary Picamera2 Access

Until the direct migration is complete, Picamera2 exposes the underlying
libcamera request. Keep its RAW stream enabled and obtain both values from one
`CompletedRequest`:

```python
request = picam2.capture_request()
try:
    image = request.make_array("main")
    raw_stream = picam2.stream_map["raw"]
    sensor_sequence = request.request.buffers[raw_stream].metadata.sequence
finally:
    request.release()
```

Do not combine `capture_array()` with `capture_metadata()`; they can consume
different frames.

## Data Sent to STM32

For each vision frame, query or look up the IMU sample using
`sensor_sequence`, then keep that sequence with the image and all derived
detections. A stream restart starts the Unicam sequence from zero, so the
STM32-side history must be reset or tagged with a matching pipeline generation
at the same time.
